# PersistentKeyValueKit 2.0.0 Release Notes

PersistentKeyValueKit 2.0.0 adds typed key migration between stores, introduces checked format-aware conversion on representations and primitive types, and updates `URL` storage in `NSUbiquitousKeyValueStore`.

## What's New

### Store-to-Store Key Migration

`PersistentKeyValueStore` now provides `copy(_:to:onConflict:completion:)` and `move(_:to:onConflict:completion:)` for transferring a single key or a heterogeneous batch of keys (`[any PersistentKeyProtocol]`) between stores:

```swift
guard let destination = UserDefaults.migratable(suiteName: "group.example.app") else {
    return
}

let report = try UserDefaults.standard.move(
    [.runtimeColorScheme, .launchCount],
    to: destination,
    onConflict: .keepBoth,
    completion: .once(id: "app-group-preferences-v1", recordedIn: destination)
)
```

- **Persisted-domain reads and conflict detection**: Migration inspects only values persisted in a store's own domain. Registered defaults (`UserDefaults.register`), launch arguments (`UserDefaults.argumentDomain`), added suites (`UserDefaults.addSuite(named:)`), and a key's `defaultValue` are not migrated from the source and do not count as destination conflicts.
- **Conflict policies**: Copy operations require `PersistentKeyCopyConflictPolicy` (`.keepDestination` or `.overwriteDestination`). Move operations require `PersistentKeyMoveConflictPolicy` (`.keepBoth`, `.overwriteDestination`, or `.keepDestinationAndRemoveSource`).
- **Structured reporting**: Every migration returns a `PersistentKeyMigrationReport` containing ordered per-key outcomes (`PersistentKeyMigrationReport.Outcome`) and the completion-tracking state (`PersistentKeyMigrationReport.Completion`). Setup errors (`PersistentKeyMigrationError`) are thrown before any key is modified; per-key failures are recorded in the report with their `FailureStage` (`.snapshot`, `.decode`, `.prepare`, `.write`, or `.cleanup`) while the rest of the batch continues.
- **Migratable named `UserDefaults` suites**: `UserDefaults.migratable(suiteName:)` creates a native `UserDefaults` instance and attaches the suite name as process-local metadata so migration can read and verify its persistent domain directly. It returns `nil` when the suite name is empty, matches a reserved domain (`argumentDomain`, `registrationDomain`, `globalDomain`, `kCFPreferencesAnyApplication`, or `kCFPreferencesCurrentApplication`) or `Bundle.main.bundleIdentifier` ignoring case, or cannot be created by Foundation. Migration treats suite names that differ only by case as the same store.
- **Optional once-only completion tracking**: Passing `.once(id:recordedIn:)` records `.isMigrationCompleted(id:)` in the specified store after all keys in the batch resolve without failure. Later calls with the same `id` and recording store skip the migration and return `completion: .alreadyRecorded`.
- **Per-key migration eligibility**: `PersistentKeyProtocol.isMigrationEnabled` controls whether a key participates in migration (`true` by default). `PersistentDebugKey` enables migration in Debug builds and disables it in Release builds, reporting `.keyDisabled`.

### Checked Representation Conversion

`PersistentKeyValueRepresentation` and `PrimitiveKeyValuePersistible` now expose throwing, format-aware conversion methods used by migration and direct validation:

- `PersistentKeyValueRepresentation.decode(storageObject:format:) throws -> Value`
- `PersistentKeyValueRepresentation.encode(_:format:) throws -> Any?`
- `PrimitiveKeyValuePersistible.decode(storageObject:format:) throws -> Self`
- `PrimitiveKeyValuePersistible.encode(format:) throws -> Any?`

`PersistentKeyValueStorageFormat` identifies `.propertyList`, `.userDefaults`, or `.ubiquitousKeyValueStore`. Built-in conversion failures throw `PersistentKeyValueConversionError` (`.invalidStorageValue`, `.invalidValue`, or `.encodingFailed`), while `CodablePersistentKeyValueRepresentation` preserves the underlying `Encoder` and `Decoder` errors. Ordinary store `get` and `set` methods remain non-throwing.

## Breaking Changes and Upgrade Guide

### 1. Direct `PersistentKeyValueRepresentation` Conformances

`PersistentKeyValueRepresentation` now requires `decode(storageObject:format:)` and `encode(_:format:)`.

- **No changes required** if your types use `ProxyPersistentKeyValueRepresentation`, `RawRepresentablePersistentKeyValueRepresentation`, `CodablePersistentKeyValueRepresentation`, `LosslessStringConvertiblePersistentKeyValueRepresentation`, or conform to `ProxyPersistentKeyValueRepresentationProtocol`. `ProxyPersistentKeyValueRepresentationProtocol` provides default implementations backed by your existing `from(_:)` and `to(_:)` methods.
- **Action required** if you have a type that conforms directly to `PersistentKeyValueRepresentation`: implement `decode(storageObject:format:)` and `encode(_:format:)`. Return `nil` from `encode(_:format:)` when the key should be removed from the store.

```swift
extension CustomRepresentation: PersistentKeyValueRepresentation {
    func decode(storageObject: Any, format: PersistentKeyValueStorageFormat) throws -> Value {
        guard let string = storageObject as? String, let value = Value(parsing: string) else {
            throw PersistentKeyValueConversionError.invalidStorageValue
        }
        return value
    }

    func encode(_ value: Value, format: PersistentKeyValueStorageFormat) throws -> Any? {
        value.serializedString
    }
}
```

### 2. Custom `PrimitiveKeyValuePersistible` Conformances

`PrimitiveKeyValuePersistible` now requires `static func decode(storageObject:format:)` and `func encode(format:)`.

- **No changes required** for built-in primitive types (`Bool`, `Int`, `Float`, `Double`, `String`, `Data`, `URL`, `Array`, `Dictionary`, `Optional`).
- **Action required** if you conform a custom type to `PrimitiveKeyValuePersistible`:

```swift
extension CustomPrimitive: PrimitiveKeyValuePersistible {
    static func decode(storageObject: Any, format: PersistentKeyValueStorageFormat) throws -> Self {
        guard let number = storageObject as? NSNumber else {
            throw PersistentKeyValueConversionError.invalidStorageValue
        }
        return Self(rawValue: number.intValue)
    }

    func encode(format: PersistentKeyValueStorageFormat) throws -> Any? {
        NSNumber(value: rawValue)
    }
}
```

### 3. Custom `PersistentKeyValueStore` Conformances

`PersistentKeyValueStore` now requires `var migrationEndpoint: PersistentKeyValueMigrationEndpoint { get throws }`.

- **Action required** if you define a custom `PersistentKeyValueStore` wrapper or test double: forward your backing store's `migrationEndpoint`. A store that cannot participate in migrations can throw its own error.

```swift
extension ForwardingStore: PersistentKeyValueStore {
    var migrationEndpoint: PersistentKeyValueMigrationEndpoint {
        get throws {
            try base.migrationEndpoint
        }
    }
}
```

### 4. `URL` Storage Format in `NSUbiquitousKeyValueStore`

Writing a `URL` to `NSUbiquitousKeyValueStore` now stores `url.absoluteString` (`String`) instead of passing a `URL` instance directly to `NSUbiquitousKeyValueStore.set(_:forKey:)`. This matches `NSUbiquitousKeyValueStore`'s property-list storage requirements and `URL`'s `.propertyList` representation.

- Reading a `URL` from `NSUbiquitousKeyValueStore` continues to accept legacy `URL` objects in addition to `String` values.
- `UserDefaults` retains Foundation's native `URL` storage behavior (`UserDefaults.set(_ url: URL?, forKey:)` and `UserDefaults.url(forKey:)`), storing file URLs as tilde-abbreviated paths and non-file URLs as `NSKeyedArchiver` data.

### 5. Named `UserDefaults` Suites in Migrations

Ordinary `UserDefaults(suiteName:)` instances continue to work for `get`, `set`, `remove`, and observation, but cannot participate in `copy` or `move` because Foundation does not expose an instance's writable suite name. Construct named suites that will participate in migrations with `UserDefaults.migratable(suiteName:)`.

## Other Changes

- `InMemoryPersistentKeyValueStore` now preserves an explicit entry when an optional key is set to `nil`, distinguishing stored `nil` from an unset or removed key during migration. Migrating a stored `nil` from an in-memory store to `UserDefaults` or `NSUbiquitousKeyValueStore` with `.overwriteDestination` removes the destination key.
- `PersistentKeyValuePublisher` now releases emitter ownership while holding its internal state lock so concurrent change notifications cannot be missed between the final demand check and emitter handoff.
